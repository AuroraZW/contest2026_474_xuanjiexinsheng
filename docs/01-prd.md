# 食衡产品需求文档（规格冻结版）

版本：1.0.0　产品形态：openvela 可穿戴快应用　状态：冻结

## 1. 产品定义

食衡面向容易忘记记录饮食的年轻用户，以餐时提醒、腕上快速确认和离线能量账本降低记录成本；无网络、无手机、无 AI 服务时仍可完成核心闭环。

### 目标

- 应用每次打开或恢复时，用餐时胶囊结合当前时间段和当天记录主动提示。
- 典型一餐在 30 秒内完成记录；最近吃过和收藏套餐均可快速复用，任何写入都先进入确认页。
- 离线提供摄入、运动估算消耗、净摄入、今日余量和 7 天回顾。
- 明示热量和运动消耗均为估算，所有建议仅供生活管理参考。
- 在兼容环境用 `service.health`、`system.alarm` 和 VelaClaw 增强体验，但 P0 主流程不依赖它们。

### P2 / 明确不做

- 真实腕上录音和云端 ASR。
- 自建云服务器。
- 手机伴侣 App、蓝牙同步、小米运动健康写入。
- 云账号和多设备同步。
- 拍照识餐和条码扫描。
- 系统级灵动岛或后台常驻；餐时胶囊只是食衡前台页面内的普通组件。
- 医疗诊断、减重疗效或精确代谢预测。

模拟器 Mock、文本演示和估算数据必须标明来源及边界，不能宣称未实际跑通的系统能力已经可用。

## 2. 核心场景与闭环

早餐、午餐、晚餐或加餐前后，用户打开或恢复食衡，看到当前餐次状态，选择最近吃过、收藏套餐、目录食物或键入演示文本，检查份量与估算值后确认保存；运动后选择活动和时长；首页和历史立即展示重新计算的能量账本。

核心闭环：`打开/恢复 → 餐时胶囊 → 选择或输入 → 确认 → 保存 → 今日账本`。

## 3. 功能优先级

### P0：参赛交付闭环

1. 首次设置：只设置体重、每日热量目标、早餐/午餐/晚餐时间段并接受免责声明。每日目标默认 2000 kcal；体重必须由用户设置，不能静默套用默认体重完成引导。默认时间段为早餐 07:00–09:30、午餐 11:30–14:00、晚餐 17:30–20:30。
2. 餐时胶囊：应用每次打开或恢复时按当前时间段与当天对应餐次记录判断状态。未记录时展开，提供“现在记录 / 稍后提醒 / 本餐跳过”；已记录时收缩并显示该餐热量。稍后提醒保存下一次提示时间；当天跳过、稍后和完成状态须可区分。
3. 60 项本地食物目录：交付验收固定 60 项稳定 ID，覆盖常见类别，使用单一每百单位能量事实源，每项记录数据来源；第三方数据和素材最终列入 `THIRD_PARTY_NOTICES`。
4. 快速记录：支持最近吃过、收藏套餐、分类目录和记餐页内的“一句话记餐（模拟器转写模式）”。这是键入的转写文本，不是录音或语音识别。典型一餐目标在 30 秒内完成；收藏套餐不超过 3 次点击即可进入确认页，仍须确认后保存。
5. 确认后保存：确认页显示餐次、食物、实际份量、逐项估算和合计；点“确认保存”前不得写正式账本，取消不留记录，重复提交幂等。
6. 每日能量账本：显示摄入、运动估算消耗、净摄入、今日余量，以及早餐、午餐、晚餐完成状态。
7. 六类运动固定估算：快走 3.5、跑步 8.0、骑行 6.8、跳绳 10.0、力量训练 5.0、瑜伽 2.5；以上是冻结演示 MET 值，确认后保存。
8. 记录维护：餐食和运动均可修改、删除；操作后首页汇总和历史立即回算。
9. 7 天历史：按本地日期展示摄入、运动估算消耗、净摄入、记录数，日明细在历史页内展开。
10. 始终可用的本地建议：根据记录情况输出温和、非医疗的规则化提示。
11. 设置：编辑档案与三个餐段，查看隐私声明，清除全部本地数据。

### P1：可选增强

1. `service.health` 健康卡：按官方 Mock 流程覆盖 HEART_RATE、SPO2、STRESS；仅页面可见时读取或订阅，离页取消。心率、血氧只展示；压力只可触发“先呼吸一分钟”“避免情绪化进食”等温和本地建议，不进入热量公式、不持久化、不诊断。能力不可用时显示“当前设备暂不支持”，不影响主流程。
2. VelaClaw 建议：仅由用户主动触发；10 秒失败或超时回退本地建议。应用绝不接收或存储 key，用户只在 goldfish `ai_agent` 官方配置界面私下输入 `tp-` key；不向 AI 发送不存在、推断出的健康或个人数据。
3. `system.alarm`：仅当能力可用时申请系统闹钟。不可用时，“稍后提醒”仍保存下一次提示时间，并在应用下次打开或恢复时判断和提示。该能力不是 P0 阻塞项。

## 4. 页面与导航

共七个主要页面：首次设置、首页、记餐、确认、运动、历史、设置。

```text
首次设置 → 首页
首页 → 记餐（最近吃过 / 收藏套餐 / 目录 / 文本演示）→ 确认 → 首页
首页 → 运动 → 确认 → 首页
首页 → 历史（页内展开日明细）
首页 → 设置
```

餐时胶囊、今日看板、建议和健康卡均在首页；文本演示在记餐页；餐食与运动共用确认页，不为一次性功能新增主要页面。

## 5. 关键交互

### 首次设置

1. 用户输入体重；未输入有效体重不能完成首次设置。
2. 每日热量目标预填 2000 kcal，可修改。
3. 三个餐段预填早餐 07:00–09:30、午餐 11:30–14:00、晚餐 17:30–20:30，可修改且需校验。
4. 用户阅读并接受免责声明后完成设置；完成状态持久化，重启不重复，设置页可修改上述内容。

### 餐时胶囊与提醒

- 每次应用打开或从后台恢复时重新判断当前本地时间、当天该餐记录和 `mealPromptState`。
- 当前餐未记录时展开，提供“现在记录 / 稍后提醒 / 本餐跳过”；已记录时收缩并显示该餐热量。
- “稍后提醒”由用户选择下一次提示时间并保存。仅当 `system.alarm` 可用时申请系统闹钟；失败或不可用要如实提示，仍在下次打开/恢复时判断。
- “本餐跳过”只影响当天该餐提示；新增、修改或删除餐食后应重新计算该餐状态。

### 目录与快捷记录

- 食品目录以 `energyKcalPer100` 为唯一能量事实源，份量只是输入方式，不另存一套基准热量。
- 最近吃过和收藏套餐均为 P0；选择后必须进入确认页，不能一触即写入。
- 收藏套餐目标是不超过 3 次点击进入确认；整餐流程以 30 秒内完成为验收目标，不以固定点击数限制所有入口。

### 一句话记餐（模拟器转写模式）

入口醒目标注“这是键入的转写文本，不是录音或语音识别”，不得出现麦克风、录音波形或“识别中”等暗示。

- 输入最多 80 字、最多解析 12 个片段；规范名和别名按最长匹配优先。
- 仅整段消费匹配文本，支持有限中文/阿拉伯数字，以及每个食品条目明确声明的单位。
- 只有完全没有数量时，才可使用界面明确展示的默认份量。
- 数字无单位、单位不支持、未知词、否定语义均保留为待处理，禁止静默保存或模糊猜测。
- 解析返回 `complete | needs_review | empty`、`recognizedItems` 和 `unknownSegments`（同时保留设计兼容字段 `items/unresolved`），只产生内存草稿，无存储副作用。
- `needs_review` 必须由用户处理后方可进入可保存状态。

### 确认、维护与今日看板

- 餐食和运动遵循“草稿—确认—提交”；返回、取消、超时、退出均不提交。
- 首次点保存后禁用按钮；同一记录 ID 只写一次。餐食和运动均支持修改、删除，完成后首页汇总和历史立即回算。
- 摄入 = 当日餐食千卡之和。
- 运动估算消耗 = 当日运动估算千卡之和。
- 净摄入 = 摄入 − 运动估算消耗。
- 今日余量 = 每日目标 − 净摄入。
- 同一看板显示早餐、午餐、晚餐完成状态。
- 界面明确标注“估算”和“仅供生活管理参考”，不评价健康风险。

## 6. 数据、隐私与免责声明

- 档案、餐食、运动、最近项、收藏和餐时提示状态默认仅存设备本地，最多保留 30 天；无账号、无手机同步。
- 损坏或未知版本状态不得覆盖，显示明确的损坏状态提示和清除入口。
- 清除须二次确认，完成后应用内不可恢复。
- VelaClaw 调用前展示实际将发送的最小文字摘要；不发送健康值、完整历史或不存在的个人数据，取消即不发送。
- 固定声明：“食衡中的热量、MET 消耗和建议均为估算，仅供生活管理参考，不构成医疗、诊断、治疗或专业营养建议。如有疾病、过敏、孕期或饮食障碍等情况，请咨询合格专业人士。”

## 7. 可量化验收标准

| 编号 | 标准 |
| --- | --- |
| AC-01 | 首次设置完成后持久化；重启不重复，体重、日目标和三个餐段可在设置页修改。 |
| AC-02 | 离线可浏览/搜索 60/60 条目；ID 唯一、每项有来源且仅有一个每百单位能量事实源。 |
| AC-03 | 典型一餐在 30 秒内完成；收藏套餐不超过 3 次点击进入确认，确认前记录数不变。 |
| AC-04 | 取消、退出草稿、双击保存分别新增 0、0、1 条。 |
| AC-05 | 文本演示明示“不是录音或语音识别”；待处理片段解决前不能静默保存。 |
| AC-06 | 给定食品、实际数量和每百单位能量，单项及合计公式误差不超过 1 kcal。 |
| AC-07 | 六类冻结运动均可记录；给定体重、时长和 MET 的估算误差不超过 1 kcal。 |
| AC-08 | 本地午夜正确归日；最近 7 个自然日明细与账本合计一致。 |
| AC-09 | 仅保留最近 30 个自然日，第 31 天旧数据在维护后清理。 |
| AC-10 | 断网且 health/alarm/VelaClaw 均不可用时，餐食、运动、账本、历史和本地建议仍可用。 |
| AC-11 | HEART_RATE、SPO2、STRESS 只在首页健康卡可见时读取/订阅并在离页取消；不可用显示“当前设备暂不支持”；AI 10 秒失败回退。 |
| AC-12 | 胶囊正确呈现稍后、当天跳过和已完成状态；alarm 失败不伪造成功，下次打开/恢复仍可提示。 |
| AC-13 | 修改或删除餐食/运动后首页与历史立即回算；应用重启后已确认记录仍保留。 |
| AC-14 | 清除需二次确认，完成后档案、记录、最近项、收藏和餐时状态不可见。 |
| AC-15 | 全应用无真实录音、云端 ASR、系统级灵动岛、手机同步或医疗能力宣称。 |
| AC-16 | 深色表盘背景、暖橙餐食状态、绿色完成状态、大数字和圆角卡片清晰一致；以 480×480 圆屏为主，并检查方屏和窄屏不溢出。 |
